After implementation

1. Service account with domain-wide delegation

about 20 min · ma1-google-dwd-setup

Peek resolves group grants by calling the Admin SDK Directory API as a service account that impersonates a Workspace admin. CI cannot exercise this, so it is set up by hand.

Done when: peekd starts without a configuration error and logs google group lookup enabled.

2. Verify grants, groups and versions

about 30 min, plus up to 5 min of cache wait · ma2-verify-grants-groups-versions

This checks behaviour against real Workspace data and a real browser: the 403 page, nested groups, the 400 and 404 mappings, cache expiry and version URLs. It needs the staging server from item 1 running a build of feat/page-grants-versions with Google login enabled in Settings, plus three test users: A (uploader), B (member of a test group), and C (in your domain, not in the group).
