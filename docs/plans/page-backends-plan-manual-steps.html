Page Backends Checklist

The steps only a person can do for the page backends feature. Nothing is needed before implementation; one end-to-end check runs after the last phase merges into feat/page-backends, before the pull request merges. Ticks are saved in this browser only.

Before implementation

Nothing to do. Every phase builds against a fake container runtime, and CI's backend-integration job tests against a real Docker daemon.

After implementation

1. Run the contact-form example end to end

about 40 minutes ·

This checks what CI cannot: the browser relay through peek.fetch, real email delivery, the idle stop and cold start, cleanup on delete, and the operator setup on a real machine. Mailpit catches the email, so no SMTP account or password is involved.

You need a Linux machine (or a Linux VM) with Docker Engine 24 or newer and the Docker Compose plugin, plus Go via mise to build the CLI. On macOS or Windows, Docker Desktop works too because peekd runs in a container here. Install guide: docs.docker.com/engine/install.

Report back: tick the item in the pull request and paste one line into it:

ma1-compose-end-to-end: PASS (email received, idle stop, cold start, delete cleanup)

or, if something failed, ma1-compose-end-to-end: FAIL at step N followed by what you saw and the output of docker compose logs peek-backends | tail -50.
