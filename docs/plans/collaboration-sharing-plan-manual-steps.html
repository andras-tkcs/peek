Peek sharing rollout checks

These are the checks that only you can do for the collaboration-sharing plan. None are needed before implementation. Do these four after the last phase merges and before the feature PR merges, on a staging Peek running the PR's build.

0 of 0 steps done

Before implementation

Nothing. Every phase builds and tests against fakes (a fake SMTP server, a fake mail sender, a fake Google group checker).

After implementation

1. Real SMTP: test email and a share notification

~20 min

CI only talks to a fake SMTP server. This checks TLS, authentication, real delivery and how the link looks in a real mailbox.

Report in the PR: ma1-smtp-live: pass (relay name, TLS mode) or fail plus the toast text and the share notification failed / test email failed server log line.

2. Dashboard rows and role icons

~10 min

Tests check the markup. Whether a row now reads clearly is your call.

Report: ma2-dashboard-look: pass, or what looked wrong with a screenshot.

3. Upgrade a copy of real data

~15 min

Migration 15 is tested on a synthetic database. This confirms that real password pages become restricted and that their owners can still open them.

Report: ma3-upgrade-copy: pass (N password pages → restricted), or fail plus the query output.

4. No invites under Google org sign-in

~5 min

Confirms the wording change on the configuration you use.

Report: ma4-google-org-admin: pass, or the text that still mentions invites.
