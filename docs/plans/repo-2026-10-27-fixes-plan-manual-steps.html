After implementation

Do items 1 to 5 while the feature PR is open, before you merge it. Do item 6 right after the merge. Each item ends with a line to paste into the PR.

1. Allow only merge commits

about 3 min
ma1-merge-commits-only · SEC-9

The project now says PRs land as merge commits only (CONTRIBUTING and the devflow profile). GitHub still offers squash and rebase, so the settings have to match.

Paste into the PR:
ma1 merge commits only: done

2. Turn on private reporting, Dependabot and CodeQL

about 5 min
ma2-security-features · SEC-3, SEC-4, SEC-8

The new SECURITY.md sends reporters to GitHub's private reporting form, which only works once it is enabled. Dependabot alerts and security updates, and CodeQL scanning, are settings rather than code.

Paste into the PR:
ma2 private reporting, Dependabot alerts + security updates, CodeQL default setup: done

3. Protect release tags

about 4 min
ma3-release-tag-ruleset · SEC-2

The release workflow now refuses a tag whose commit is not on main or fails tests, but anyone with write access could still push, move or delete a v* tag. A tag ruleset stops that.

Paste into the PR:
ma3 tag ruleset "release tags" (v*, admin bypass): done

4. Check the Actions defaults

about 2 min
ma4-actions-settings · review, GitHub settings step 5

The review could not read these two settings through the API. They limit what a workflow from a malicious PR could do.

Paste into the PR (fill in what you found):
ma4 workflow permissions: read-only (was: ___); fork PR approval: all external contributors

5. Look at the screenshots and pull the MinIO images

about 5 min
ma5-visual-and-compose-check · WEB-1, SEC-10

Only a person can judge the regenerated screenshots. The pinned MinIO image tags in docker-compose.yml could not be checked from Claude's container.

Paste into the PR:

6. Make the new CI jobs required

about 5 min
ma6-required-checks · SEC-1

Do this right after you merge the PR. A required check that has never run on main would block every other open PR until it rebases.

Today only build is required, so the Docker integration test and the new jobs can fail and the PR still merges.

Paste as a comment on the merged PR:
ma6 required checks (7), strict, conversation resolution: done; Pages + Docker (main) ran after merge: pass / fail
